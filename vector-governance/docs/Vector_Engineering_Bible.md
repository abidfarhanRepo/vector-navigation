# Vector Engineering Bible

## Purpose
This document is the single source of truth for every AI engineering agent working on Vector.

## Golden Rules
1. Never duplicate existing work without evaluating open-source alternatives.
2. Respect all software licenses.
3. Prefer modular, testable services.
4. Every feature requires documentation and automated tests.
5. Security, privacy, and performance are first-class requirements.

## Repository Standards
- Monorepo or well-defined multi-repo.
- Conventional commits.
- Mandatory code review (AI + human).
- CI/CD for every merge.

## Research Workflow
Discover → Clone → Read Docs → Analyze Code → Extract Architecture → License Review → Summarize → Knowledge Graph → Integration Proposal.

## Definition of Done
- Code implemented
- Tests passing
- Documentation updated
- Benchmarks recorded
- Security review completed
- Observability added

## Architecture Goals
- Offline-first
- Cloud-native
- Event-driven
- API-first
- Horizontally scalable
- Vendor-independent where practical

## Knowledge Graph
Every analyzed repository becomes indexed engineering knowledge for future agents.

## Long-Term Mission
Build the world's most advanced independent mapping and navigation platform without depending on proprietary map providers for core functionality.
